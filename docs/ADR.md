# 기술 결정 기록

팀장이 한 서버에서 시연하고 여러 휴대폰이 같은 결과를 조회할 수 있는 구성을 우선한다.

## ADR-001 · Next.js App Router와 TypeScript

네 화면은 각각 독립된 URL을 갖는다. 서버 컴포넌트와 공통 레이아웃을 사용해 직접 접속과 새로고침 때도 같은 화면이 열린다. 이후 데이터 변경 기능을 실행하려면 Node.js 서버가 필요하다.

## ADR-002 · 파일 기반 SQLite

Node.js 22.13 이상에서 내장 node:sqlite를 사용한다. 별도의 DB 서비스 없이 재시작 후에도 같은 파일을 열 수 있다. 운영 환경에는 쓰기 가능한 영속 디스크가 필요하며 여러 서버 간 복제는 범위 밖이다.

## ADR-003 · Vitest와 테스트별 임시 DB

npm test는 Vitest의 파일명 필터를 그대로 받는다. 파일 기반 DB를 닫고 다시 열어 저장 결과와 무결성을 확인한다. 화면 컴포넌트의 HTML 테스트는 제목과 탐색 목적지를 검증하며 기기의 실제 레이아웃 검사는 별도로 수행한다.

## ADR-004 · 서버에서 모델 호출, DB에서 권한과 상태 결정

계획과 취합에 OpenAI를 사용한다. 모델 응답은 서버에서 구조와 참조를 검사한다. 계획 확정과 최초 배정은 같은 트랜잭션에서 처리하며 후속 업무 개방은 저장된 선행 업무 상태를 따른다. 키는 서버 환경에만 둔다. 자동 테스트는 고정 모델 응답을 사용하고 별도의 실제 모델 확인 명령으로 연결을 검증한다.

## ADR-005 · 개인 세션의 복수 팀 참여

기존 브라우저 쿠키를 개인 식별 수단으로 유지한다. SQLite에 추가 팀의 멤버 연결을 저장하고 매 요청마다 선택한 팀의 소속과 역할을 확인한다.

## ADR-006 · 업무판 폴링과 버전별 확인

기존 업무 조회 경로를 1초 간격으로 재사용하고 숨겨진 화면은 조회를 쉬게 한다. 본문이나 링크 변경에는 원본 버전을 부여하고 멤버별 열람 버전을 저장한다. 늦게 도착한 이전 버전의 열람이 최신 수정 표시를 지울 수 없도록 한다.

## ADR-007 · 운영표 동시 수정

서버는 SQLite 쓰기 트랜잭션 안에서 편집 기준 버전과 현재 버전을 비교한다. 내용이 같으면 재전송에 성공으로 응답하고, 내용이 다르고 기준이 오래되었으면 409를 반환한다. 충돌 시 사용자가 두 내용을 확인하고 반영할 부분을 선택한다.

## ADR-008 · 운영표 행과 점검 결과 연결

행 순서가 바뀌어도 같은 근거를 찾도록 원본 업무 안에서 머리글과 첫 셀이 유일한 행을 선택한다. 원본 열람은 멤버별로 기록하고 점검 조치 여부는 결과 업무에 저장한다. 결과 담당자가 표시된 버전에 대해 명시적으로 조치를 완료해야 팀 전체의 재확인 요청이 해제된다.

## ADR-009 · 팀 채팅의 주기적 공유 노트

채팅 조회 여부와 무관하게 노트를 생성하려고 상시 실행하는 Node.js 서버에서 5분 주기로 팀별 미정리 대화를 확인한다. 메시지와 완성된 노트는 기존 SQLite 파일에 보관한다. 팀원들이 동일한 요약을 다시 읽고 근거를 검토할 수 있도록 서버는 노트 항목에 원문 메시지 ID를 저장한다.
